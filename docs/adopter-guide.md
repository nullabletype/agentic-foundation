# Using the adopted playbook

The active project contract is `PROJECT.md`. It starts as a draft and grants no publication permissions until the owner accepts it. The files under `templates/` are reusable record formats, not competing project policy.

1. Choose additional reading through the [task routes](task-routing.md). For an uncertain product flow, follow [discovery](discovery.md), disposable HTML exploration and re-grilling.
2. For established or non-interactive work, record the accepted decisions and choose the smallest relevant experiment. Do not rebuild an HTML prototype for a routine repair.
3. Fill PROJECT.md with actual commands, owners and budgets. Record the [LikeC4 consideration](architecture.md) and verify the [support inventory](support-policy.md) before acceptance. Configure privacy restrictions before any agent session. Mark controls as manual, enforced-and-tested or pending.
4. Deliver one bounded task with independent verification, then review what helped and what caused unnecessary friction.

For application review, configure the contract's dedicated synthetic generator/launcher and scenario coverage; test missing-data/collision rejection without touching a real workspace. For supported security audits, validate report contents, scope and completion as described in [support policy](support-policy.md#validate-security-results). The [synthetic boundary examples](../examples/verification-boundaries.md) show expected decisions; they are not execution evidence for the adopting application.

At setup, ask whether private-data inspection is needed to understand an external format; default to disabled/not needed and use the [owner-operated inspection boundary](controls.md#optional-owner-operated-private-data-inspection) if proposed. Select [architecture checks](architecture.md#check-useful-boundaries) where useful, targeted [mutation checks](testing.md#targeted-mutation-checks) for critical rules, and tests for [selective CI](testing.md#selective-ci) when used. Configure relevant commands in PROJECT.md; dependency support/security review remains required regardless of these choices.

CREDITS.md records the adopted foundation version and links its MIT notice. Preserve these when sharing adapted guidance. The adopted files configure no tools, CI workflow, host permissions, application licence or Git settings. Use [controls](controls.md) to configure those in the chosen environment. The Foundation repository provides optional adoption and isolation tools; they are deliberately not installed into the product by this copy operation.
