# Optional subscription budget controls

These provider-specific adapters are an advanced opt-in, separate from the portable harness. No launcher or sandbox is supplied.

## Restricted, budgeted real-agent runs

`budget-broker.mjs` supplies a deliberately narrow subscription Responses broker and a durable token ledger. It is an execution component, not a sandbox launcher. A real run still requires a verified external filesystem/network/process boundary: candidates receive a private home and clean environment, the current worktree, read-only runtime files and read-only Git metadata; they receive neither host credentials nor desktop sockets. Their only external communication is the broker socket. Run command graders under equivalent restrictions, without the broker socket: a candidate can modify executable worktree files. Keep the credential, ledger, results and trusted launcher outside candidate-writable mounts. Bound scratch storage in the launcher and use `runProcess`'s `maximumOutputBytes` to terminate excessive process output.

The agreed initial baseline is six cases twice, at most three corrections per case/trial, 45 minutes for the whole run, four minutes per invocation and two million total input/output tokens through the user's Pro sign-in only. The launcher supplies no API key and offers no API-billing or credit-purchase route. The policy fixes the subscription model to `gpt-6-luna`; its 1,050,000-token context and 128,000-token output ceilings were checked against the [official model page](https://developers.openai.com/api/docs/models/gpt-6-luna) on 2026-10-17. Every request durably reserves their conservative sum, 1,178,000 tokens, before dispatch. Authoritative usage settles input plus output tokens, including reasoning already counted in output. No additional reasoning charge is added. If usage is unavailable, that reservation remains consumed and no further request is admitted. Even with usage available, a request needs the full reservation remaining; the baseline may stop below two million actually consumed tokens. Reverify the model bounds before changing the model. The subscription route has not established a usable `max_output_tokens` option, so the broker strips that option, `service_tier` and `client_metadata`, forces streaming with no stored response, and rejects hosted tools, media, opaque prior contexts and unknown options.

Usage parsing recognises complete JSON or SSE framing independently of the upstream MIME header and normalises the forwarded content type. SSE settlement requires a single completed terminal event with valid usage; truncated, conflicting or failed terminal events keep the full reservation. This parser hardening is covered by synthetic tests. It does not establish the cause of an earlier real response whose body was deliberately not retained.

The broker forwards only to `https://chatgpt.com/backend-api/codex/responses`, rejects redirects and keeps prompts, response bodies and credentials in memory only. The host supplies the signed-in access token and account ID; candidates receive neither. A mandatory trusted `beforeDispatch` callback checks included subscription quota and rejects unavailable usage or any nonzero/available credit balance before every request. The launcher must implement that callback with an authenticated, abortable quota check that returns exactly `true` only when subscription use is allowed; a no-op callback is suitable only for synthetic tests. These checks are preflight guards; they are not an atomic server-side opt-out from credit fallback. No such opt-out was established by this implementation. Candidate requests cannot select another model or destination. Policy, quota, provider and usage failures stop further admissions, with optional `onStop` receiving only a fixed operational reason for a protected stop marker. A disconnected client retains its reservation unless authoritative usage subsequently arrives. Admission is serialized and capped at 512 persisted requests, including zero-token responses. The broker permits one active upstream handler and at most 32 local connections. Shutdown denies new admissions, aborts in-flight upstream work, closes client connections and awaits the active handler before the ledger may close. Ledger writes are synchronized and atomically replaced before dispatch. An exclusive lock prevents simultaneous owners; a crash leaves that lock for operator reconciliation. Reopening the same ledger preserves consumed tokens, unresolved reservations and the original deadline. Never delete a ledger or remove a stale lock to obtain more allowance; reconcile the interrupted operation first. Wall-clock and monotonic deadlines both constrain an active broker. The `dot-orbit-token-budget:v1` ledger has explicit `tokens` entries and rejects the earlier monetary-ledger format rather than converting or resetting it.

An external launcher imports `openBudgetLedger` and `startBudgetBroker`, mounts the Unix socket into the candidate sandbox and bridges it only to that sandbox's isolated loopback if required by the CLI. Pin and record the exact candidate binary/version/hash and provider configuration. Verify with adversarial synthetic probes that direct network, unrelated files, credentials, desktop sockets, writable trusted controls and writable Git metadata are unavailable before making real model requests. Do not use this broker with a CLI that can bypass the enforced socket-only route.

`runEvaluation` accepts `processRunner` for candidate/reviewer processes and `commandRunner` for graders so the launcher can apply restrictions to every executable boundary. Supply `maximumTotalMilliseconds`, `timeoutMilliseconds`, `shouldStop`, `retainPartialResults: true` and a protected `progressPath` outside the repository, distinct from the final result path. Deadline or token-budget exhaustion stops new invocations. A bounded run adds `completion` to the v2 result: incomplete runs retain completed trial evidence and force aggregate failure. This is an additive v2 field; unbounded existing runs retain their existing shape. The progress file is synchronized and atomically replaced after each completed trial; its aggregate always reports incomplete failure. An infrastructure abort may retain partial evidence with a fixed reason and no raw exception prose. Abrupt process termination requires reconciliation from that progress file and the durable budget ledger; it is not a completed baseline.

Run the synthetic budget tests alongside the harness checks, inside an environment permitting local Unix sockets but denying external network:

```sh
node --test toolkits/agent-evaluation/budget-broker.test.mjs toolkits/agent-evaluation/harness.test.mjs
```

These tests and a new scripted-reference run are required validation of the controls. They do not replace the requested 12 real-agent trials or prove the external sandbox's enforcement.


The `dot-orbit-token-budget:v1` ledger schema and `baselinePolicy` export remain unchanged for durable-ledger compatibility. The name is a historical protocol identifier, not a dependency on dot-orbit. Reconcile existing locks/reservations; never reset a ledger to gain allowance.
